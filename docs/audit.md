**59 passed**. Current local suite: **78 Python, 9 backend, 12 Playwright tests**,
plus type/build/lint, empty-database migration, restricted-role startup,
backup/restore, failed-migration recovery, dependency scans and image builds.
GitHub CI verifies the same suite and both image scanners/SBOMs. The initially
failed API image scan was repaired by applying Debian security updates and
removing runtime npm/corepack, without relaxing the scan.
The hosted final check found that missing DB access returned generic 500
readiness; it now returns an explicit 503 blocked status, covered by an outage
regression test without secret exposure.

the machine's pre-existing database service is untouched. Docker became
available and both split images built and started. Local fixture execution is
explicitly authored test evidence, not production sandbox acceptance.

## Remaining release risks and blocked dependencies

Actual GitHub user sign-in, provider identity/selected installation, Supabase
backup/migration, restricted-role startup and idle Actions worker dispatch are
now verified. The free Session pooler replaced the unreachable direct IPv6
endpoint; runtime images carry pinned official CA roots for certificate/hostname
verification. The 24-table new schema restored into a separate local test DB.
That exercise found a timestamp comparison mismatch between UTC and
Asia/Calcutta; restore verification now normalizes its session to UTC.

E2B/Groq keys and confirmed free-entitlement variables are staged privately, but
sandbox credit admission is still zero and the template is absent. Actual E2B
isolation, bounded inference and the hosted repair/PR/recurrence journey remain
unverified. The disposable Python fixture has real failing GitHub CI evidence;
its App selection requires an owner change after 403 responses with both CLI
and actual App user credentials. No sandbox, inference or hosted verified Case
is claimed. See acceptance.md for exact results and IDs.

New-schema tenant isolation uses scoped queries and composite keys, not RLS;
the schema must stay outside Supabase's browser Data API. Free hosting has API
sleep, Actions queue delays and no unattended wakeup guarantee while both sleep.
E2B credits are bounded and one-time. JavaScript, fork PR heads and unpinned
dependency recipes remain explicitly unsupported/incomplete.

The local restore and lease-recovery checks do not establish a production
backup/PITR or distributed rollback guarantee. Production network enforcement
must pass actual E2B HTTP probes. See acceptance.md for the exact tested scope
and deployment.md for the minimal private owner setup.
